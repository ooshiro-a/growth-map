# 準備の手順（GAS・シート・GitHub）

シートと GAS は **テスト用** と **本番** の2組を作る。手順は同じで、名前と合言葉だけ変える。

| | テスト用 | 本番 |
|---|---|---|
| スプレッドシート | 成長の地図DB-テスト | 成長の地図DB |
| 置き場所 | マイドライブ/成長の地図/ | マイドライブ/成長の地図/ |
| 合言葉 | テスト用の合言葉（本番とは別。こちらも長め・4語以上がおすすめ） | 本番の合言葉（長め・4語以上がおすすめ） |
| GitHub の変数 | `GAS_URL_TEST` | `GAS_URL` |

合言葉は、コード・リポジトリ・チャットに書かない。

## 1. スプレッドシートと GAS
1. Google ドライブの「マイドライブ」に「成長の地図」フォルダを作る
2. その中に空のスプレッドシートを作り、名前を「成長の地図DB-テスト」にする
3. 「拡張機能」→「Apps Script」を開く
4. 最初からある `function myFunction() {}` を全部消し、`gas/Code.gs` の中身を全部貼って保存
5. 左の「プロジェクトの設定」（歯車）
   - 「タイムゾーン」を「(GMT+09:00) 日本標準時 - 東京」にする
   - 下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
     - プロパティ：`PASSPHRASE`　値：合言葉
6. エディタに戻り、上の関数の選択で `setup` を選んで「実行」
   - 初回は「承認が必要」→ アカウントを選ぶ →「詳細」→「（プロジェクト名）に移動」→「許可」
   - シートに `records` ができ、1行目に見出しが入る
7. 右上の「デプロイ」→「新しいデプロイ」→ 種類の歯車 →「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」を押し、表示された「ウェブアプリの URL」（`https://script.google.com/macros/s/…/exec`）を控える
8. 同じことを「成長の地図DB」（本番）でも行う（合言葉は別にする）

### 合言葉を続けて間違えて止まった時
10回続けて違うと30分止まる（画面は前回の内容を出したまま、5分ごとに読み直す）。
止まるのは合言葉を入れる所だけ。一度合言葉を入れた端末は「端末の鍵」で通るので、止まっている間も使える。
すぐ解きたい時は、Apps Script エディタで関数 `unlock` を選んで「実行」。

### 端末をなくした・鍵を使えなくしたい時
スクリプト プロパティの `PASSPHRASE` を新しい合言葉に変える。すべての端末の鍵が使えなくなり、各端末で新しい合言葉を入れ直す。

### GAS を更新する時
「デプロイ」→「デプロイを管理」→ 鉛筆（編集）→ バージョン「新バージョン」→「デプロイ」。
**新しいデプロイを作らない**（URL が変わってしまう）。

## 2. GitHub
1. https://github.com/new でリポジトリを作る
   - 名前：`growth-map`／公開（Public）／README などは付けない
2. リポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
3. Settings → Secrets and variables → Actions → **Variables** タブ → New repository variable
   - `GAS_URL`：本番のウェブアプリの URL
   - `GAS_URL_TEST`：テスト用のウェブアプリの URL
4. 最初の push のあと、Actions タブで「Deploy」が緑になれば公開完了
   - 公開 URL：https://ooshiro-a.github.io/growth-map/
   - 変数は組み立てる時に読む。変数を入れた・変えた時は Actions →「Deploy」→「Run workflow」でもう一度公開する
     （変数が空のまま組み立てると、Deploy の結果に「GAS_URL が未設定」と黄色で出て、画面は「接続先が設定されていません」になる）

## 3. 端末での初回
1. 公開 URL を開く（スマホは「ホーム画面に追加」すると開きやすい。名前は grops、アイコンは藍の海と山と太陽）
   - iPhone のホーム画面のアプリは Safari と記憶が分かれるので、置いた後に1回合言葉を入れる（しばらく使わなくても記憶は消えにくい）
   - 名前やアイコンが古いままの時は、アイコンを削除して置き直す（削除する前に、そのアプリの右上に「未保存」が無いことを確かめる）
2. 接続先（本番／テスト用）を選び、合言葉を入れる（通ると GAS から「端末の鍵」を受け取って記憶する。合言葉そのものは残さない）
3. 記憶が消えた時（iPhone でしばらく使わなかった時など）は、もう一度合言葉を入れる

## 4. 初期データの取り込み（1回だけ）
PC で行う（初期データのファイルは PC の reference/ にあり、リポジトリには入れない）。
1. テスト用で、作り物の `tools/example-seed.json` を取り込んで流れを確かめる（テスト用のシートには本物を入れない）
2. 接続先を本番にして、設定 →「初回の取り込み」→「ファイルを選ぶ」で `reference/seed-2026.json` を選ぶ（中身を貼ってもよい）
3. 「確かめる」を押すとシートを読み直す。件数の一覧と中身の例（文字化けしていないか）を確かめて「登録する」
4. 右上の「未保存」が消えれば完了。取り込みは年を問わず1回だけ（2回目は「取り込み済み」と出る）

## 5. 控えの複製と12月のお知らせ（GAS の時間指定）
GAS が毎月1日（3時台）に `records` を新しいスプレッドシートへ写し、シートと同じフォルダの「（シートの名前）の控え」フォルダに置く（古い控えは消さない）。
毎年12月25日（9時台）に「振り返りの時期です」とメールを送る（宛先は自分。別の宛先にする時はスクリプト プロパティ `NOTIFY_EMAIL`）。
最後の控えの日は、画面の「設定」→「控えとお知らせ」に出る（40日以上前なら赤で知らせる）。

### テスト用で確かめる（時間指定は作らない）
1. 「成長の地図DB-テスト」の Apps Script を開き、`gas/Code.gs` の中身を全部貼り替えて保存
2. 関数の選択で `backupNow` を選んで「実行」
   - 許可を求められる（新しい許可：スプレッドシートを作る・ドライブ・メールを送る・時間指定）→ アカウントを選ぶ →「詳細」→「（プロジェクト名）に移動」→「許可」
   - ドライブの許可は「すべてのファイル」と出るが、コードが触れるのはこのシートと控えフォルダだけ（控えをフォルダへ移すのに、この許可が要る）
   - 実行ログに「控えを作りました：成長の地図DB-テスト_控え_（日付）（N行）」と出る。ドライブの「成長の地図/成長の地図DB-テストの控え」に控えがあることを確かめる
3. `testNotice` を「実行」→ 自分に「（試し）grops：振り返りの時期です」が届く
4. 「デプロイ」→「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→「デプロイ」（**許可をした後に行う**。先にデプロイすると、画面から読めなくなることがある）
5. 画面を接続先「テスト用」で開き、「設定」→「控えとお知らせ」に最後の控えの日が出る

### 本番
1. 「成長の地図DB」の Apps Script で、上の 1〜4 と同じことをする（`backupNow` の代わりに `setupSchedule` を実行してよい）
2. 関数の選択で `setupSchedule` を選んで「実行」→ 時間指定が2つできて、控えが1つできる
   - 左の「トリガー」（時計）に `backupNow`（月ベース・1日・午前3〜4時）と `decemberNotice`（月ベース・25日・午前9〜10時）がある
   - 何回実行しても2つだけ（作り直す）。止める時は `stopSchedule`
3. 時間指定が失敗した時は、Google から「失敗の知らせ」のメールが届く

### 控えから元に戻す時（シートが壊れた時だけ）
1. 控えのスプレッドシートを開き、下の `records` タブを右クリック →「コピー先」→「既存のスプレッドシート」→「成長の地図DB」
2. 「成長の地図DB」で、壊れた `records` の名前を `records-壊れた日付` に変えて残し、コピーしたタブの名前を `records` にする
3. Apps Script で `setup` を「実行」（書式と保護をかけ直す）
